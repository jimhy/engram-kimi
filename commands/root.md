# /engram:root

把**当前目录**标记为 engram「项目管理目录」：它本身不当项目用，其下的每个直接子目录各自是一个独立项目——在某个子目录里任意深度开会话，记忆都锚定到**那个子目录**的项目库，不会再因 cwd 漂移而碎片化。

**先定位引擎二进制**（用户 PATH 里一般没有 `engram`）：在 `$KIMI_CODE_HOME/plugins/managed/engram/bin/`（`KIMI_CODE_HOME` 缺省为 `~/.kimi-code/`）下按平台选 `engram-windows-x86_64.exe` / `engram-macos-aarch64` / `engram-macos-x86_64` / `engram-linux-x86_64`。下文命令里的 `engram` 都指这个绝对路径（`ENGRAM_BIN` 环境变量已设定时优先用它）。

执行：

```bash
engram root --project-dir "$PWD"
```

引擎会：
1. 沿父链检查——若某个祖先已是项目管理目录，**拒绝**（不允许嵌套，这是**唯一**的拒绝条件）；
2. 当前目录已是管理目录 → 幂等成功返回；
3. 否则在当前目录建 `.engram/`（`workspace` 标记 + 管理库；若目录已有 `.engram/` 库——例如 hook 自动建过——则复用、保留其内容），并往公共库写一条 L2 记忆登记「此目录是项目管理目录」。

成功后引擎会打印该管理目录的绝对路径。把结果转告用户：
- **成功**：告诉他「`<路径>` 已设为项目管理目录；以后在它下面建子目录即各自成独立项目，别直接在这里写项目」。
- **被拒**（仅当嵌套在已有的项目管理目录之下）：原样转达拒绝原因。

允许多个**平行**的项目管理目录（彼此不可嵌套）。
